# pat2bmp 取扱説明書

ROMなどのバイナリデータから各種ビットマップフォントやパターンデータを抽出し、1bpp（白黒2値）のBMP画像を生成するコマンドラインツールです。

Pythonスクリプト（`pat2bmp.py`）としての実行に加え、PyInstallerでビルドした実行ファイル（`pat2bmp.exe`）でも動作します。

---

## 主な特徴

- **多様なフォント形式に対応**:
  - `8x8`, `8x16`, `16x8`, `16x16` などのリニアな並びの他、MSXのスプライトのような左右分割（`8x16x2`, `16x16SPRITE`）、MSXの漢字ROMで用いられるZ並びのタイル（`16x16Z`, `16x16KANJI`）、MSXView等で用いられる2ライン3バイトのパックド形式（`12x8`, `12x12`）に対応。
- **外部設定ファイル対応**:
  - テキスト形式（`.cfg`）および JSON形式（`.json`）に対応。
  - アドレスや文字数には `0x` 接頭辞、`H` 接尾辞の16進表記や乗算式（`256*2` 等）が使用可能。
  - アドレス指定を `()` で囲むことで、ROM内の16ビットLE値（ポインタ）による間接参照に対応。
  - JSONはコメントと末尾の余分なカンマを許容する拡張仕様。
- **アスペクト比調整 & ドット拡大**:
  - 縦拡大（`-v`）や横拡大（`-h`）など、縦横スケーリング倍率の指定に対応。
  
---

## 動作環境

- **実行ファイル（.exe）を使用する場合**:
  - Windows 64bit 環境（Pythonのインストールは不要）
- **Pythonスクリプトを使用する場合**:
  - Python 3.7 以上（標準モジュールのみで動作）

---

## 使い方

### 基本的なコマンド例

**exeファイルの場合:**
```bat
pat2bmp.exe <入力ROMファイル> <出力BMPファイル> [オプション]
```

**Pythonスクリプトの場合:**
```bash
python pat2bmp.py <入力ROMファイル> <出力BMPファイル> [オプション]
```

### 使用例

```bat
# 組み込みのデフォルト設定で抽出（MSX BIOS フォント、横幅256px、等倍）
pat2bmp.exe msxbios.rom output.bmp

# 外部設定ファイル (font.cfg) を使用し、横幅512px、縦2倍で出力
pat2bmp.exe rom.bin output.bmp -c font.cfg -w 512 -v 2

# 外部設定ファイル (font.cfg) を使用し、横幅512px、横2倍で出力
pat2bmp.exe rom.bin output.bmp -c font.cfg -w 512 -h 2

# JSON設定ファイルを使用
pat2bmp.exe rom.bin output.bmp -c font.json
```

## コマンドライン引数

| 引数 / オプション | 説明 | デフォルト値 |
| :--- | :--- | :--- |

| `-v`, `--vscale` | 縦方向の拡大倍率（整数） | `1`（等倍） |

## データ配置図

- **1ドット＝1ビット**（白黒2値）です。
- 各バイト内の8ビットは、**最上位ビット（Bit 7 / MSB）が左端ドット、最下位ビット（Bit 0 / LSB）が右端ドット**に対応します。

### 16×8形式のデータ配置図（1文字：16バイト）

横16ドット × 縦8ドットにおける格納バイト（Offset: 0〜15）の対応関係です。

#### 8x8x2 / 16x8H（左右分割順：8×8タイルで左右分割）
左の8×8ブロック（8バイト）を上から下へ格納した後、右の8×8ブロック（8バイト）を上から下へ配置。  
※8×8ドットのグリフを水平（Horizontal）に2文字分連結した構造です。

```text
    0       7 8      15 (Xドット)
   +---------+---------+
 0 | Byte    | Byte    |
   |  0 ～ 7 |  8 ～ 15|
 7 | (左 8x8)| (右 8x8)|
   +---------+---------+
(Yドット)
```

#### 16x8 / 16x8L（水平走査順：ラスタースキャン）
1ライン（16ドット＝2バイト）を左から右へ、上から下へとラスタースキャン順に配置。

```text
    0       7 8      15 (Xドット)
   +---------+---------+
 0 | Byte  0 | Byte  1 |  (0ライン目)
 1 | Byte  2 | Byte  3 |  (1ライン目)
 2 | Byte  4 | Byte  5 |  (2ライン目)
   |   ...   |   ...   |
 7 | Byte 14 | Byte 15 |  (7ライン目)
   +---------+---------+
(Yドット)
```

### 16×16形式のデータ配置図（1文字：32バイト）

各形式における 16×16 ドット領域と格納バイト（Offset: 0〜31）の対応関係です。

#### 8x16x2 / 16x16H / 16x16SPRITE（MSXスプライト形式：8×16タイルで左右分割）
左列（8×16ドット）を上から下へ格納した後、右列（8×16ドット）を上から下へ配置。

```text
    0       7 8      15 (Xドット)
   +---------+---------+
 0 | Byte    | Byte    |
   |  0 ～ 7 | 16 ～ 23|
 7 | (左上)  | (右上)  |
   +---------+---------+
 8 | Byte    | Byte    |
   |  8 ～ 15| 24 ～ 31|
15 | (左下)  | (右下)  |
   +---------+---------+
(Yドット)
```

#### 16x16Z / 16x16KANJI（MSX漢字ROM形式：8×8タイルをZ順に配置）
8×8ドットの4ブロック（A, B, C, D）を、左上 → 右上 → 左下 → 右下の順に配置。

```text
    0       7 8      15 (Xドット)
   +---------+---------+
 0 |    A    |    B    |
   | Byte    | Byte    |
 7 |  0 ～ 7 |  8 ～ 15|
   +---------+---------+
 8 |    C    |    D    |
   | Byte    | Byte    |
15 | 16 ～ 23| 24 ～ 31|
   +---------+---------+
(Yドット)
```

#### 16x16 / 16x16L（水平走査順）
1ライン（16ドット＝2バイト）を左から右へ、上から下へとラスタースキャン順に配置。

```text
    0       7 8      15 (Xドット)
   +---------+---------+
 0 | Byte  0 | Byte  1 |  (0ライン目)
 1 | Byte  2 | Byte  3 |  (1ライン目)
 2 | Byte  4 | Byte  5 |  (2ライン目)
   |   ...   |   ...   |
15 | Byte 30 | Byte 31 |  (15ライン目)
   +---------+---------+
(Yドット)
```

### 12×8 / 12×12形式のデータ配置図（2ライン3バイト パックド形式）

MSXView等で採用されている横12ドットのフォントは、1ライン（12ドット）がバイト単位（8ビット）で割り切れないため、**連続する2ライン（計24ドット）を3バイトに詰めて格納**するパックド方式となっています。

- **`12x8` / `12x8VIEW`**：2ライン3バイト × 4組 ＝ **1文字あたり 12バイト**
- **`12x12` / `12x12VIEW`**：2ライン3バイト × 6組 ＝ **1文字あたり 18バイト**

#### 2ライン（3バイト＝Byte A, B, C）のビット対応関係

```text
(偶数ライン 2n)
Xドット: 0        7 8        11
        +----------+----------+
        |  Byte A  |  Byte B  |  (8ドット + 4ドット = 12ドット)
        | bit 7～0 | bit 7～4 |
        +----------+----------+

(奇数ライン 2n+1)
Xドット: 0    3 4            11
        +------+--------------+
        |Byte B|    Byte C    |  (4ドット + 8ドット = 12ドット)
        |bit3～0   bit 7～0   |
        +------+--------------+
```

| ライン | X: 0 〜 3 | X: 4 〜 7 | X: 8 〜 11 |
| :--- | :--- | :--- | :--- |
| **偶数ライン (2n)** | `Byte 3n+0` (bit 7〜4) | `Byte 3n+0` (bit 3〜0) | `Byte 3n+1` (bit 7〜4) |
| **奇数ライン (2n+1)** | `Byte 3n+1` (bit 3〜0) | `Byte 3n+2` (bit 7〜4) | `Byte 3n+2` (bit 3〜0) |

※半角文字（6×8 / 6×12ドット）も同一のバイト長・フォーマットで格納されており、右側6ドット（X: 6〜11）が `0`（空白）でパディングされています。

## ROM媒体と一般的な開始アドレス（オフセット）一覧

各種ROMダンプファイル（生バイナリ）から各フォントを抽出する際の、代表的なオフセットおよび設定例です。

### 1. 標準漢字ROM（生ROMダンプイメージ）

| ROMイメージの種類 | 全体容量 | 抽出対象 | 開始アドレス | 文字数 | 形式 |
| :--- | :---: | :--- | :---: | :---: | :---: |
| **第1水準 単体ROM** | 128KB | JIS第1水準＋非漢字 | `0x00000` | 4,096 | `16x16KANJI` |
| **第2水準 単体ROM** | 128KB | JIS第2水準 | `0x00000` | 4,096 | `16x16KANJI` |
| **第1＋第2水準 統合ROM**<br>(MSX2+/turbo R 内蔵ROM等) | 256KB | JIS第1水準＋非漢字<br>JIS第2水準 | `0x00000`<br>`0x20000` | 4,096<br>4,096 | `16x16KANJI`<br>`16x16KANJI` |

### 2. MSXView付属 漢字ROMカートリッジ (256KB メガROM)

* **マッパー仕様**: ASCII 8Kバンク（8KB × 32バンク = 256KB）
* **ROMヘッダ識別子**: Bank 0 の `0x00010` 〜 `0x0001A` に `'MSXViewKROM'`
* **ブロック配置の順序**: 前半に **12×12フォント**、後半に **12×8フォント** が配置されています。

カートリッジ全体（256KB）をリニアにダンプした場合の正確なブロック配置：

| 収録フォントブロック | サイズ | 開始アドレス | 枠文字数 | 形式 |
| :--- | :---: | :---: | :---: | :---: |
| **カートリッジヘッダ領域** | 8KB | `0x00000` | - | - |
| **12×12 半角英数 (20H〜7FH)** | 1,728バイト | `0x02000` | 96 | `12x12` |
| **12×12 全角非漢字 (1〜8区)** | 13,824バイト | `0x026C0` | 768 | `12x12` |
| **12×12 半角カナ (A0H〜DFH)** | 1,152バイト | `0x05CC0` | 64 | `12x12` |
| *(空白・Zero Fill)* | 1,728バイト | `0x06140` | - | - |
| **12×12 全角第1水準 (16〜47区)** | 55,296バイト | `0x06800` | 3,072 | `12x12` |
| **12×12 全角第2水準 (48〜84区)** | 63,936バイト | `0x14000` | 3,552 | `12x12` |
| *(空白・Zero Fill)* | 1,600バイト | `0x239C0` | - | - |
| **12×8 半角英数 (20H〜7FH)** | 1,152バイト | `0x24000` | 96 | `12x8` |
| **12×8 全角非漢字 (1〜8区)** | 9,216バイト | `0x24480` | 768 | `12x8` |
| **12×8 半角カナ (A0H〜DFH)** | 768バイト | `0x26880` | 64 | `12x8` |
| *(空白・Zero Fill)* | 1,152バイト | `0x26B80` | - | - |
| **12×8 全角第1水準 (16〜47区)** | 36,864バイト | `0x27000` | 3,072 | `12x8` |
| *(以降 空白領域)* | 64KB | `0x30000` | - | - |

> ※Extended View font（拡張版）では、`0x30000`〜`0x3A67F` に 12×8 第2水準漢字（3,552文字枠）が追加収録されます。

### 3. FS-A1GT 内蔵ファームウェアROM (松下メガROM)

* **マッパー仕様**: Panasonic Mapper（本体内蔵ファームウェアROM空間に格納）
* **収録内容**: **12×12（第1水準のみ）**、**12×8（第1水準のみ）**
  * ※FS-A1GTの内蔵ROMには容量の都合上、**12×12のJIS第2水準は収録されていません**。
  * 内蔵ROMダンプにおける代表的な配置オフセット:
    * 12×12 第1水準ブロック群: `0x140000`〜（半角: `140000H`, 1〜8区: `1406C0H`, カナ: `143CC0H`, 16〜47区: `144800H`）
    * 12×8 第1水準ブロック群: `0x1C0000`〜（半角: `1C0000H`, 1〜8区: `1C0480H`, カナ: `1C2880H`, 16〜47区: `1C3000H`）

## 設定ファイルの書き方

### 1. `.cfg` 形式
スペースまたはカンマ区切りで `開始アドレス`, `文字数`, `形式` の順に記述します。  
`#` または `;` 以降はコメントとして扱われます。

```text
# 開始アドレス, 文字数, 形式
0x2B400, 96, 8x8
0x2B700, 94, 16x8
0x2BCE0, 2,  8x8x2
0x7E000, 256*2, 16x8
(0x0004), 96, 8x8   # 0x0004にある16bit LE値をアドレスとして参照
```

### 2. `.json` 形式
配列形式（リスト形式）またはオブジェクト形式で記述できます。

```json
[
  // 配列形式: [アドレス, 文字数, "形式"]
  ["0x2B400", 96, "8x8"],
  ["2B700H", 94, "16x8"],
  ["(0x0004)", 96, "8x8"],

  // オブジェクト形式
  {
    "address": "0x7E000",
    "count": "256*2",
    "format": "16x8"
  }
]
```

### 数値表記の仕様
設定ファイル内のアドレスや文字数には以下の記法が使用できます：
- 10進数: `96`
- 16進数 (0x): `0x2B400`
- 16進数 (Hサフィックス): `2B400H`
- 乗算式: `256*2`, `16*16`
- アドレス間接参照（開始アドレスのみ）: `(0x0004)`, `(4000H)`
  - `()` で囲まれたオフセットから2バイトを読み出し、16ビットリトルエンディアン（LE）値として得られたアドレスを実際のフォント開始位置として使用します。

## 設定ファイルの記述例

### 例1: MSX BIOS ANK文字フォント

ankfont.cfg

```text
# MSX BIOS ANK文字フォント
# 開始アドレス, 文字数, 形式
(0x0004), 256, 8x8    # アドレス0004Hに書かれたアドレスに256文字のフォントがある
```

### 例2: 256KB 統合標準漢字ROM 

kanjifont.cfg

```text
# 256KB 統合漢字ROM (第1水準 + 第2水準)
# 開始アドレス, 文字数, 形式
0x00000, 4096, 16x16KANJI    # 第1水準 + 非漢字 (128KB / 131,072バイト)
0x20000, 4096, 16x16KANJI    # 第2水準 (128KB / 131,072バイト)
```

### 例3: MSXView付属 漢字ROMカートリッジ

msxview_rom.cfg

```text
# =============================================================================
# MSXView付属 漢字ROMカートリッジ (256KB メガROM) フォント定義
# 書式: 開始アドレス, 文字数, 形式
# =============================================================================

# -----------------------------------------------------------------------------
# 12x12 フォント群
# -----------------------------------------------------------------------------
0x02000,   96, 12x12    # 12x12 半角英数 20H～7FH (96文字 / 1,728バイト)
0x026C0,  768, 12x12    # 12x12 全角非漢字 1～8区 (768文字枠 / 13,824バイト)
```
