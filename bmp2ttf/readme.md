# bmp2ttf2 取扱説明書

画像（BMP / PNG等）に並べられたビットマップパターンから等幅およびプロポーショナルの TrueType フォント（`.ttf`）を生成するツールです。

一般的な画像グリッドからの文字切り出し機能に加え、Unicode の私用領域（外字領域）へ独自のフォントを取り込み、定義ファイル（`.def`）を用いて任意の通常文字（ASCII、ひらがな、カタカナ、漢字等）へマッピングして利用できる機能を備えています。また、文字幅に応じたプロポーショナルフォントの生成と、ゲームプログラム等で利用可能なメトリクスデータ（`_proportional.txt`）の自動出力に対応しています。

---

## 配布形式と動作環境

本ツールは **Windows向け実行ファイル（`.exe`）** と **Python スクリプト（`.py`）** の両方を同梱しています。

### exe 版を利用する場合
- Python 等の環境構築は不要です。そのままコマンドプロンプトや PowerShell から実行できます。
- コマンド例における `python bmp2ttf2.py` を `bmp2ttf2.exe` に読み替えて実行してください。

### Python スクリプト版を利用する場合
- Python 3.10 以上
- 必要ライブラリ:
  ```bash
  pip install pillow fonttools
  ```

## 基本的な使用方法

単一画像を素早く変換する簡易CLI指定、複数領域を指定するCLI直接指定、および設定ファイル（JSON）を指定する方法があります。

### 単一画像を簡易指定して実行する
画像ファイルを直接指定するだけで、8×8 セルのフォントを即座に生成できます。
フォント名や出力ファイル名を省略した場合は、入力画像名に基づいて自動決定されます。
```bash
# 基本的な変換（font.ttf が生成されます）
bmp2ttf2.exe font.bmp

# 名前や出力先を明示して変換
bmp2ttf2.exe font.bmp -n "MyFont" -f "MyFont Family" -o output.ttf

# セルサイズや余白・ベースラインをドット数で指定
bmp2ttf2.exe font.bmp -s 8x8 -b 1 -mt 1 -mb 1 -o output.ttf
```

### CLI から複数セットを直接指定して実行する
```bash
# 等幅フォントの生成
bmp2ttf2.exe -o output.ttf --set "font.png:0,0,256,48:8,16:0x0020" --set "font.png:0,48,256,688:16,16:0x3040"

# プロポーショナルフォントの生成 (-p / --proportional)
bmp2ttf2.exe -o output.ttf --set "font.png:0,0,256,48:8,16:0x0020" -p
```

### JSON 設定ファイルを指定して実行する（推奨）
```bash
# 設定ファイル名に基づいた TTF が生成されます (config.json なら config.ttf)
bmp2ttf2.exe -c config.json

# 出力先を明示する場合
bmp2ttf2.exe -c config.json -o output.ttf
```

## フォント名・出力ファイル名の決定ルール

フォント名（`name`）、ファミリー名（`family`）、および出力ファイル名（`-o`）は、以下の優先順位に従って統一的に自動決定されます。

- **明示指定名**: コマンドライン引数（`-n`, `-f`）または JSON 内で指定された名前を最優先します。
  - `--name` のみ指定時: `family` にも同名を補完します。
  - `--family` のみ指定時: `name` にも同名を補完します。
- **設定ファイル名**: 指定名が無い場合、JSON設定ファイルのベース名（例: `config.json` なら `config`）を採用します。
- **画像ファイル名**: 設定ファイルも無い場合、単一画像のベース名（例: `font.bmp` なら `font`）を採用します。
- **出力ファイル名 (`-o`)**: 省略時は決定されたベース名に `.ttf` を付与したファイル名（例: `config.ttf`, `font.ttf`）になります。

## ベースライン・余白の指定仕様

ベースライン（`-b`）や余白（`-m`, `-mt`, `-mb`）は、**実ドット数** または **セル高さに対する比率** で指定できます。

- **ドット数指定（基本）**: 単なる数値（整数・小数問わず）はすべてドット数として扱われます。
  - 例: `1`（1ドット）、`1.5`（1.5ドット）、`0`（0ドット）
- **分数比率指定**: `/` を含めると分数比率として計算されます。
  - 例: `1/8`、`2/16`
- **パーセント指定**: 末尾に `%` を付けるとパーセント比率として計算されます。
  - 例: `12.5%`、`25%`

---

## 画像の切り出し仕様（セル間隔と有効サイズ）

文字ごとの間隔（ピッチ）と、実際に文字として切り出す領域サイズを個別に指定できます。

- **書式（CLI）**: `間隔幅,間隔高[/有効幅,有効高]` （例: `16,16` または `16,16/8,16`）
- **書式（JSON）**: `"step_size": [16, 16], "glyph_size": [8, 16]`

```text
- セル間隔 (step_size: 16x16) : 外枠 [+] (1文字あたりの配置ピッチ)
- 有効サイズ (glyph_size: 8x16): 左側 [#] (実際の切り出し幅)

+----+----+
|####|    |  <- 16x16 のセル枠から左側 8x16 のみを取得
|####|    |     送り幅 (Advance Width) はセル間隔 (16)
|####|    |     ではなく指定した有効幅 (8) となる
+----+----+
```
- 間隔と有効サイズが同一の場合は有効サイズの指定を省略できます（`glyph_size` を省略すると `step_size` と同じになります）。

---

## BBOX（切り出し領域）の検証とエラー表示

`--set` や JSON の `bbox` に不正な座標が指定された場合、原因を特定しやすい詳細情報が表示されます。

- **終点座標の逆転・負数（`x2 <= x1` または `y2 <= y1`）**:
  幅や高さが負になっていることを指摘します。また、`[X, Y, 幅, 高さ]` 形式と混同している可能性を検知した場合、正しい `[x1, y1, x2, y2]` の指定候補を自動サジェストします。
- **画像サイズ超過**:
  画像の幅・高さをどれだけ超過しているかをドット数単位でピンポイントに表示します。
- **セル未満サイズ（0セル問題）**:
  指定された領域サイズがセルサイズより小さく、文字を 1 つも切り出せない場合に中断します。

## プロポーショナルフォント生成機能

`-p`（または `--proportional`）を指定すると、文字ごとにドットが存在する実幅を自動検出し、可変幅（プロポーショナル）フォントを生成します。

```text
|<--- (送り幅) --->|
|[ ### ]           |
|[#   #]           |
|[#   #]           |
|[#####]           |
|[#   #]           |
|<---->|<--------->|
文字実幅 右マージン(字間)
(width)  (char_spacing)
 ※ LSB = 0 (左詰め)
```

- **グリフ配置**: 文字内のドットが存在する最小X位置を原点（`X=0`, `LSB=0`）に揃えて左詰めで配置します。
- **文字送り幅（Advance Width）**: `(文字実幅 + 字間スペース) × dot_scale` で計算されます。
- **空白文字（スペース等）の送り幅**: ドットが存在しない文字には、指定された空白幅（デフォルトはセル切り出し有効幅の最小値）を割り当てます。
- **フォントヘッダ設定**: 等幅フラグ（`post.isFixedPitch = 0`）および PANOSE 比率（`OS/2.panose.bProportion = 0`）がプロポーショナル用として適切に設定されます。

## メトリクス定義ファイル（`_proportional.txt`）の出力

プロポーショナル指定時（`-p`）、出力TTFファイルと同階層・同名で **`{出力名}_proportional.txt`** が自動生成されます。自作ゲームエンジンや描画ルーチンで文字セルを直接テクスチャから切り出して描画する際に、そのまま配列データとして活用できます。

### 出力書式（配列形式）

PythonのリストやJSON（配列の配列）として扱いやすい角括弧形式です。行頭に `//` によるカラム説明ヘッダが付きます。文字マップ（`--charmap`）を適用している場合、`"char"` には割り当てられた実際の文字が出力されます。

```text
// index, [cell_x, cell_y, pad_x, pad_y], offset_x, width, "char"
[   0, [   0,   0, 0, 0], 1, 6, "!" ],
[   1, [   8,   0, 0, 0], 1, 6, "\"" ],
[   2, [  16,   0, 0, 0], 1, 6, "#" ],
[   3, [  24,   0, 0, 0], 0, 8, "W" ],
[  10, [  80,   0, 0, 0], 0, 0, " " ],
[ 256, [   0,  64, 0, 0], 0, 8, "あ" ],
[ 257, [   8,  64, 0, 0], 0, 8, "\u00A0"]
```
※最終行の末尾にはカンマ（`,`）が付きません。

### カラム仕様

| カラム | 内容 | 説明 |
| :--- | :--- | :--- |
| `index` | 通し番号 | 0から始まる文字インデックス（整数） |
| `cell_x`, `cell_y` | セル左上座標 | 元画像上の該当セルの切り出し開始ピクセル座標 |
| `pad_x`, `pad_y` | パディングサイズ | セル間隔と有効サイズの差分（`step_w - glyph_w`, `step_h - glyph_h`） |
| `offset_x` | 切り出し横オフセット | セル内において実際にドットが始まる相対Xピクセル座標 |
| `width` | 実文字幅 | ドットが存在する部分の横ピクセル幅（スペース等は `0`） |
| `"char"` | 割り当て文字 | 文字列リテラル（ダブルクォートや制御文字はUnicodeエスケープ） |

## スケールコピー機能（`--scale-copy`）

取り込んだグリフを横50%に縮小し、指定した別のコードポイント領域へ複製グリフとして登録する機能です（全角グラフィックフォントから半角フォントを派生生成する場合などに使用します）。

- **書式（CLI）**: `--scale-copy コピー元,コピー先,文字数`
  - 例: `--scale-copy 0xE000,0xE100,256`
  - 3つの値をカンマ区切りで指定します。未指定時は縮小コピーを行いません。
- **書式（JSON）**:
  ```json
  "scale_copy": ["0xE000", "0xE100", 256]
  ```
  ※`{"src": "0xE000", "dst": "0xE100", "count": 256}` や `"0xE000,0xE100,256"` 形式も受け付けます。

---

## 文字マップ機能（`--charmap` / .def ファイル）

ビットマップから取り込んだ文字（またはスケールコピーした文字）を、定義ファイル（`.def`）に基づいて通常の文字コード（ASCII、かな、漢字等）へマッピング（二重割り当て）します。

```text
[画像から取得] ──> 外字領域 (U+E000〜) に登録
                         │
                         ▼  (--charmap でマッピング)
                   通常文字 (ASCII, かな, 漢字等) でも入力・表示可能に
```

- **書式（CLI）**: `-cm パス[,参照元コードポイント]` または `--charmap パス[,参照元コードポイント]`
  - 例（参照元を明示）: `--charmap char_map.def,0xE000`
  - 例（参照元を省略）: `--charmap char_map.def`（先頭セットの開始コードポイントが自動適用されます）
  - 未指定時は文字マッピング処理を行いません。
- **書式（JSON）**:
  ```json
  "charmap": ["char_map.def", "0xE000"]
  ```
  ※`{"file": "char_map.def", "source": "0xE000"}` や `"char_map.def,0xE000"`、ファイルパス単体の `"char_map.def"` 形式も受け付けます。

## 定義ファイル（.def）の書式仕様

行単位のテキストファイルです。各行で「開始オフセット」と「配置する文字列」を指定します。

```text
; セミコロンで始まる行はコメント
+20	 !"#$%&'()*+,-./0123456789:;<=>?
+40	@ABCDEFGHIJKLMNOPQRSTUVWXYZ[¥]^
100	悪宿扱安暗闇以偉慰異移敵一印飲院
```

### 構文規則

- **オフセットと文字列の区切り**: 必ず **タブ文字（`\t`）1文字** で区切ってください（スペース区切りは無効です）。
- **開始オフセットの指定**: **16進数** で指定します。先頭の `+` 記号はあっても無くても構いません（`+20`, `20`, `+100`, `100` のいずれも有効）。
  - 指定したオフセット値から、タブ以降の文字列が 1 文字ずつ順番に配置されます。
  - 途中のオフセットが飛んでいる場合は未定義（スキップ）として扱われます。
- **エスケープシーケンス**: `\` によるエスケープが有効です（`\u0000`, `\t`, `\"`, `\\` 等）。
- **コメント・空行**: 行頭が `;`（セミコロン）の行、および空行は無視されます。

## オプション・パラメータ一覧

### コマンドライン引数 (CLI)

| オプション | 引数 | 説明 |
| :--- | :--- | :--- |
| `input`（位置引数） | ファイル名 | 入力画像ファイルパス（単一画像指定用。省略時は `--set` または `-c` が必要） |
| `-o`, `--output` | ファイル名 | 出力先 TTF ファイル名（省略時は設定名・画像名・フォント名に準拠） |
| `-n`, `--name` | 文字列 | フォント名（省略時は `--family` と同一、または設定名・画像名） |
| `-f`, `--family`, `--family-name` | 文字列 | フォントファミリー名（省略時は `--name` と同一） |
| `-c`, `--config` | パス | 設定用 JSON ファイルのパス |
| `--set` | 書式指定 | 画像セット指定: `画像パス:x1,y1,x2,y2:間隔[/有効]:開始コード` |
| `-s`, `--cell-size` | 文字列 | 単一画像指定時のセルサイズ（例: `8x8`, `16x16`。デフォルト: `8x8`） |
| `-cw`, `--cell-width` | 整数 | 単一画像指定時のセル幅 |
| `-ch`, `--cell-height` | 整数 | 単一画像指定時のセル高 |
| `--em`, `--units-per-em` | 整数 | EM値（16〜16384、デフォルト: `1024`） |
| `-b`, `--baseline` | 数値/比率 | ベースライン（ドット数、`1/8` などの分数、または `12.5%` などのパーセント。デフォルト: `1/8`） |
| `-m`, `--margin` | 数値/比率 | 上下共通の余白（ドット数、分数、またはパーセント） |
| `-mt`, `--margin-top` | 数値/比率 | 上余白（ドット数、分数、またはパーセント） |
| `-mb`, `--margin-bottom` | 数値/比率 | 下余白（ドット数、分数、またはパーセント） |
| `-p`, `--proportional` | なし | プロポーショナルフォントとして生成し、`_proportional.txt` を出力 |
| `--char-spacing` | 整数 | 字間スペース（ドット数、デフォルト: `1`）<br>※ `--proportional` 指定時のみ有効 |
| `--space-width` | 整数 | 空白文字の送り幅（ドット数、デフォルト: セル切り出し有効幅の最小値）<br>※ `--proportional` 指定時のみ有効 |
| `--scale-copy` | 書式指定 | 横50%縮小コピーの指定: `コピー元,コピー先,文字数` |
| `-cm`, `--charmap` | 書式指定 | 文字マップ定義ファイルの指定: `定義ファイルパス[,参照元コードポイント]` |

## JSON 設定ファイル仕様

```json
{
  "name": "MyFont",
  "family": "MyFont Family",
  "em": 1024,
  "baseline": 1,
  "margin": 1,
  "proportional": true,
  "char_spacing": 1,
  "space_width": 4,
  "sets": [
    {
      "image": "font.png",
      "bbox": [0, 0, 256, 48],
      "step_size": [8, 16],
      "start_cp": "0xE020"
    },
    {
      "image": "font.png",
      "bbox": [0, 48, 256, 688],
      "step_size": [16, 16],
      "start_cp": "0xE080"
    }
  ],
  "scale_copy": ["0xE000", "0xE100", 256],
  "charmap": ["char_map_normal.def", "0xE000"]
}
```

### JSON パラメータ項目

- `name`: フォント名（省略時は `family`、設定ファイル名、または画像名）。
- `family` または `family_name`: フォントファミリー名（省略時は `name` と同一）。
- `em` または `units_per_em`: EM値（`unitsPerEm`）。
- `baseline`: ベースライン（数値ならドット数、`"1/8"` などの分数、`"12.5%"` などのパーセント）。
- `margin` / `margin_top` / `margin_bottom`: 上下の余白（ドット数、分数、またはパーセント）。
- `proportional`: `true` でプロポーショナルフォント化およびテキスト出力。
- `char_spacing`: 字間ドット数（デフォルト: `1`。※ `proportional: true` 時のみ有効）。
- `space_width`: 空白文字の送り幅ドット数（デフォルト: 切り出し最小幅。※ `proportional: true` 時のみ有効）。
- `sets`: 画像切り出し設定の配列。
  - `image` (必須): 画像ファイルパス。
  - `step_size` または `cell_size` (必須): `[幅, 高さ]` のセル間隔ピッチ。
  - `glyph_size` (任意): `[幅, 高さ]` の切り出し・送り幅サイズ。省略時は `step_size` と同値。
  - `bbox` (任意): 画像内の走査領域 `[x1, y1, x2, y2]`。省略時は画像全体。
  - `start_cp` (必須): 開始コードポイント（`"0xE000"`, `57344` 等）。
- `scale_copy`: スケールコピー指定（`["コピー元", "コピー先", 文字数]` 等）。省略時は実行しません。
- `charmap`: 文字マップ指定（`["定義ファイルパス", "参照元コードポイント"]` 等）。省略時は実行しません。

## 【実践例】ハイドライド3（MSX2版）フォントの生成

ハイドライド3のメッセージシステムは独自のマルチバイト体系を持っています。
- 基本コード: `20H` 〜 `FFH`
- 拡張文字（漢字等）: `FEH` と `FFH` をプレフィックスとし、それぞれ 256 文字分の拡張コード領域を持ちます。

同梱の `hydlide3_msx2.bat` では
- [`pat2bmp`](./pat2bmp.md) を使用して、`HYDL3MSX2.ROM` から `hydlide3_msx2_font.bmp` （幅256 × 高さ688 ピクセル）を作成し、
- 次に [`bmp2ttf2`](./bmp2ttf2.md) を使用して、`hydlide3_msx2_font.bmp` と `char_map_hydlide3_main.def` を渡してTrueTypeフォント（ttfファイル）を生成します。

### hydlide3_msx2.bat
```bat
@set rom=hyd3m2v2.rom
@set bmp=hydlide3_msx2_font.bmp
@set cfg=hydlide3_msx2_font_extract.cfg
@set json=hydlide3_msx2.json
py pat2bmp.py %rom% %bmp% -c %cfg% --vscale 2
py bmp2ttf2.py -c %json%
timeout /t 5
```

### pat2bmp用 設定ファイル （`hydlide3_msx2_font_extract.cfg`）

書式：[pat2bmp.md](./pat2bmp.md) を参照

```text
# =============================================================================
# フォント定義ファイル (fonts.cfg)
#
# 書式: 開始アドレス, 文字数, ビット形式
#
# ・開始アドレス: 16進数 (0x2B400 または 2B400H) / 10進数
# ・文字数      : 10進数 / 乗算式 (例: 256*2)
# ・ビット形式  : 8x8, 16x8, 8x8x2
# ・コメント    : '#' または ';' 以降はすべてコメント
# =============================================================================

# アスキーコード 20H～7FH (96文字, 8x8)
2B400H,  96,    8x8

# MSXアスキーコード 80H～FFH (計128文字)
# ※ DEH, DFH (濁点・半濁点) は 8x8x2 形式
2B700H,  94,    16x8    ; 80H～DDH (通常16x8)
2BCE0H,  2,     8x8x2   ; DEH～DFH (濁点・半濁点: 8x8タイル×2)
2BD00H,  32,    16x8    ; E0H～FFH (通常16x8)

# 漢字ブロック (256*2個, 16x8)
7E000H,  256*2, 16x8    # 16x16行 * 2ブロック
```

### hydlide3_msx2_font.bmp のレイアウト構成

| 領域（Y座標） | 内容 | セル仕様 (幅×高) | 文字数 | コード範囲 |
| :--- | :--- | :--- | :--- | :--- |
| `0` 〜 `48` (3行) | 半角英数記号 | **8×16** (32文字/行) | 96文字 | `0x20` 〜 `0x7F` |
| `48` 〜 `176` (8行) | 全角かな・記号 | **16×16** (16文字/行) | 128文字 | `0x80` 〜 `0xFF` |
| `176` 〜 `432` (16行) | 拡張文字 [FEH] | **16×16** (16文字/行) | 256文字 | `0x100` 〜 `0x1FF` |
| `432` 〜 `688` (16行) | 拡張文字 [FFH] | **16×16** (16文字/行) | 256文字 | `0x200` 〜 `0x2FF` |

全グリフを外字領域 `0xE000` 基準（`+20` は `0xE020`、`+80` は `0xE080`、`+100` は `0xE100`、`+200` は `0xE200`）へ取り込み、`.def` ファイルによって Unicode（ASCII、ひらがな、カタカナ、漢字）へ割り当てます。

### bmp2ttf2 実行部

# exe 版の場合
