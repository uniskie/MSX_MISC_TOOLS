# MSX 漢字ROM 形式変換ツール (`convert_msx_kanji.py`)

MSX規格の漢字ROMにおける **「物理マスクROM形式（ROMライター吸い出し形式）」** と **「リニア形式（エミュレータ用形式）」** を相互変換するPythonスクリプトです。  
システム全体の複合ファームウェアイメージからのオフセット指定・切り出し変換にも対応しています。

---

## 概要・なぜこのツールが必要なのか？

MSXで漢字ROM（JIS第1水準/第2水準）を扱う際、**データの取得方法によってデータの並び順が異なる**というハードウェア上の特殊仕様が存在します。

| 形式 | 主な用途・ファイル名 | 内部の並び順 |
| :--- | :--- | :--- |
| **物理ROM形式**<br>(ハードウェアダンプ) | 実機のマスクROM、ROMライターで直接吸い出した生データ、実機修理用のROM焼き | 32K byteごとに4象限（左上・右上・左下・右下）へ分散配置されている |
| **リニア形式**<br>(ソフトウェアダンプ) | 各種エミュレータ（openMSX, blueMSX等）用の `KANJI.ROM` / `KANJI1.ROM` / `KANJI2.ROM` | 1文字（32 byte）ずつ順番に「左上→右上→左下→右下」と並んでいる |

### 配列の違いが発生する理由
MSX実機の漢字ROMコントローラ回路（東芝HX-M200等に由来する回路）は、フォントを8 byte読み出すごとにカウンタによってROMの上位アドレス線（A15, A16など）を切り替える配線になっています。  
そのため、**ROMライターで吸い出した生データをそのままエミュレータに読み込ませても文字化けし、逆にエミュレータ用の `KANJI.ROM` をそのままROMに焼いて実機に乗せても正常に表示されません。**

本ツールを使用することで、この両者を正しく相互変換できます。

---

## 主な機能

- **相互変換:**
  - 物理生ROM ➡ エミュレータ用リニアROM
  - エミュレータ用リニアROM ➡ 実機ROM焼き用生ROM（`-r` オプション）
- **容量・水準対応:**
  - JIS第1水準（128K byte / 0x20000）
  - JIS第1＋第2水準（256K byte / 0x40000）
- **複合ROMからの切り出し:**
  - ファームウェア全体ダンプ等から、特定アドレス（オフセット）を指定して該当領域のみを変換・抽出可能

---

## 動作要件

- Python 3.6 以上（標準ライブラリのみを使用するため、外部パッケージのインストールは不要）

---

## 使い方

```bash
python convert_msx_kanji.py <入力ファイル> [オプション]
```

### オプション一覧

| オプション | 引数 | 説明 |
| :--- | :--- | :--- |
| `-o`, `--output` | `<パス>` | 出力ファイル名を指定します。（省略時は自動生成） |
| `-s`, `--offset` | `<数値>` | 漢字領域の開始オフセットを指定します（16進数 `0x...` または 10進数）。デフォルトは `0x0`。 |
| `-L`, `--level`  | `1` または `2` | 抽出・変換する水準を指定します（`1`: 128K byte, `2`: 256K byte）。 |
| `-l`, `--size`   | `<数値>` | 切り出すバイトサイズを明示的に指定します（例: `0x20000`）。 |
| `-r`, `--reverse`| なし | **逆変換モード**。リニア形式から実機焼き用生ROM形式へ変換します。 |

---

## 使用例

### 1. 実機から吸い出したROMをエミュレータ用にする（基本）
ROMライターで吸い出した生ROMファイル（128K byteまたは256K byte）を変換します。
```bash
python convert_msx_kanji.py raw_dump.bin -o KANJI.ROM
```

### 2. エミュレータ用の `KANJI.ROM` を実機ROM焼き用に戻す（逆変換）
エミュレータで使用しているROMイメージを、実機搭載用のROM（27C010 / 27C020 など）に焼くための配置へ変換します。
```bash
python convert_msx_kanji.py KANJI.ROM -r -o burned_kanji.bin
```

### 3. メガROMやシステムダンプからオフセットを指定して切り出す
システムROM全体のダンプファイル（例: 512K byteや2M byteなど）に含まれる漢字ROM領域を切り出して変換します。

- **0x80000 から 256K byte（第1＋第2水準）を切り出す場合:**
  ```bash
  python convert_msx_kanji.py firmware.bin -s 0x80000 -L 2 -o KANJI.ROM
  ```

- **0x40000 から 128K byte（第1水準のみ）を切り出す場合:**
  ```bash
  python convert_msx_kanji.py firmware.bin -s 0x40000 -L 1 -o KANJI1.ROM
  ```

## 内部データ構造の詳細

16×16ドットの漢字フォント（1文字あたり32 byte）は、8×8ドット（8 byte）のブロック4つで構成されます。

```text
+------------+------------+
|    左上    |    右上    |
| (TL: 8byte)| (TR: 8byte)|
+------------+------------+
|    左下    |    右下    |
| (BL: 8byte)| (BR: 8byte)|
+------------+------------+
```

### 物理生ROM（32K byte × 4バンク）の配置 (第1水準 128K byte の場合)
- **`0x00000 - 0x07FFF` (32K byte):** 全4,096文字の **左上 (TL)** ブロック
- **`0x08000 - 0x0FFFF` (32K byte):** 全4,096文字の **右上 (TR)** ブロック
- **`0x10000 - 0x17FFF` (32K byte):** 全4,096文字の **左下 (BL)** ブロック
- **`0x18000 - 0x1FFFF` (32K byte):** 全4,096文字の **右下 (BR)** ブロック

### リニア形式の配置
- **`0x00000 - 0x0001F` (32 byte):** 文字0（TL 8 byte ➡ TR 8 byte ➡ BL 8 byte ➡ BR 8 byte）
- **`0x00020 - 0x0003F` (32 byte):** 文字1（TL 8 byte ➡ TR 8 byte ➡ BL 8 byte ➡ BR 8 byte）
- 以降、文字単位で連続配置。
